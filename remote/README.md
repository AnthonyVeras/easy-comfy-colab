# Remote runtime

This directory is a clean implementation for the new application. It never reads the legacy runtime image. Its only install root is `/content/easy-comfy-colab-2`, and its only persistent root is `/content/drive/MyDrive/EasyComfyColab2`.

## Bootstrap contract

The controller uploads this directory through its owned SFTP channel and mounts Google Drive through the Colab kernel. Invoke `python3 /content/easy-comfy-colab-2/remote/bootstrap.py --stdin`; send a JSON object through the SSH channel stdin. The sole stdout line is `{ok,result}` or `{ok:false,error:{code,message}}`. Never pass a bearer token in process arguments.

Prepare fields: `action:"prepare"`, `account_id`, `session_id`, `nonce`, `bearer_token` (32–256 URL-safe characters), `gpu` (`CPU|T4|L4|A100|G4|H100`), `output_mode` (`pc|drive`). Subsequent actions require the identical account/session/nonce. Supported actions: `start`, `restart`, `freeMemory`, `health`, `report`, `runtime.save`, `outputs.prepare`, `outputs.ack` (ack object in `params`), `resume`, `stop`, and `stop_unprepared`. Stop only reports a verified gate. The controller owns VM unassignment; this subsystem never unassigns a VM.

`stop_unprepared` is limited to a failed initial prepare: full identity, GPU, output mode and bearer must match; no installed marker, any service record, service listener or output file may exist. Explicit `lstat` skips only `FileNotFoundError`; permission/I/O failures and directory traversal failures block teardown. It returns `{safe_to_stop:true,unprepared:true,installed:false,runtime_required:false,pending_outputs:0}` with session identity. Nothing new requires preservation and prior Drive artifacts remain untouched. A prepared session always uses its normal output/runtime gates.

Restart can switch PC/Drive in the same VM with `{output_mode:<target>,previous_output_mode:<current>}`. The controller must first capture/copy/ack the current destination and preserve the runtime. Bootstrap pauses admission, terminates only the verified owned ComfyUI PID, waits for its port to close, then changes the companion's persisted output destination and starts ComfyUI at the new path. Identity/nonce and both output directories remain intact. Health/start report actual `output_mode`. If service readiness fails after the mode is committed, that actual mode remains recorded; recover/reconnect to it instead of claiming an old destination was restored. Retry starts the same owned VM from its actual config. The live first GPU proof uses the sources it started with; newly uploaded source files do not reload a running companion. New versions are activated on a fresh owned runtime, not by interrupting active generation.

CPU starts only the download companion. GPU creates two virtual environments that inherit the Colab base. The owned T4's first real attempt exposed a Colab Python 3.13 base with pip but no ensurepip. Environments now use standard `venv --without-pip --system-site-packages`, verify their own interpreter prefix and inherit base pip. Re-running the same creation completes a partially created environment without clearing its contents. No apt/driver/base-pip installation is performed. Protected Torch/CUDA packages must keep their base versions and locations. No drivers, Torch stack, or external environments are replaced. Core Git SHA, compatible frontend/Manager, MCP and CLI versions are pinned in `runtime.json`. An initial PyPI-only, binary-only resolution produces SHA-256 wheel locks; subsequent installation uses `--require-hashes --no-deps`. Required inherited dependencies are recorded separately so relevant Colab base drift forces a clean installation instead of restoring an incompatible artifact.

Start listens exclusively on `127.0.0.1`: ComfyUI 8188, companion 8190, official MCP 8189. The controller must verify companion identity, ComfyUI `/system_stats`, and a successful MCP `server_info`. The pinned CLI's actual environment result is `server.running`, `config.default_workspace`, and optional `hardware.gpu`; these differ from an older MCP docstring. MCP HTTP is stateless JSON under `/mcp`. Health returns identity/ports/paths and never credentials.

## Companion API

Every request requires `Authorization: Bearer ...`, `X-Easy-Account`, `X-Easy-Session`, `X-Easy-Nonce`. No credentials appear in responses or disk job metadata. JSON request limit is 1 MiB except `/workflows/check`, `/workflows/import`, and `/outputs/ack`, which allow 16 MiB including wrapper fields, measured in UTF-8 bytes. At most one request larger than 1 MiB is parsed at a time; HTTP concurrency remains 16. Output manifests contain at most 10,000 files with relative paths limited to 1,024 UTF-8 bytes; this bounds the full acknowledgment within 16 MiB. Pages have `offset` and `limit` (1–100). Successful responses wrap the result.

| Endpoint | Behavior |
| --- | --- |
| GET `/health`, `/snapshot` | Identity, real available measurements, bounded first pages. Unknown measurements are null. Snapshot does not claim fresh runtime verification. |
| GET `/models`, `/downloads`, `/nodes` | `{items,total,offset,limit}`. Node listing requires pinned Manager. |
| GET `/workflows` | Paginated `.json` files under the new Drive workflow root: `{items:[{name,relative_path,remote_path,size,modified}],total,offset,limit}`. No symlinks or legacy directories; at most 10,000 files, relative paths up to 1,024 UTF-8 bytes. |
| GET `/legacy/files?kind=model\|workflow&category=...` | Explicit same-account legacy picker; model category required, workflow category absent. `{items:[{id,kind,category,source_category,name,relative_path,size,modified}],total,offset,limit}`. Paths are relative to the selected source category or workflow root. Target `llm_gguf` lists both fixed old `LLM` and `llm_gguf` folders with distinct IDs and source categories. |
| POST `/legacy/import` | `{kind,category?,source_category?,relative_path,destination_name?}` imports one selected file without moving/deleting its original. Target filename is a basename up to 255 UTF-8 bytes with its original extension. Receipt includes `imported,source_preserved,sha256,size,name,relative_path,newrelative_path,remote_path,unchanged`. Conflicting content requires another filename. CPU and GPU ready sessions are accepted; active background work, generation or paused admission blocks import. |
| GET `/nodes/catalog?query=...`, `/nodes/versions?id=...` | Official public Registry discovery with `{items,total,offset,limit}`; versions also include `id`. Catalog items expose `id,name,description,installed,version,latest_version,compatibility`; version items expose `version,compatibility`. Active, nondeprecated stable releases only; no arbitrary installer URLs. Known incompatible Linux/CUDA/core/frontend constraints block changes. Missing/unparseable constraints are explicitly unknown, and a metadata match does not prove execution. |
| POST `/downloads` | `{urls,category,parallel,tokens}`; 1–50 URLs, 1–6 workers. Entry is a URL, `URL \| filename`, or `{url,filename,sha256?}`. HF blob/resolve URLs accepted; Civitai `/api/download/models/<version>` requires explicit filename. Tokens are memory only. |
| POST `/downloads/<id>/cancel` or `/resume` | Cancels cooperatively; resume checks source identity, ETag, Range, length and optional SHA. Resume tokens may be supplied in body. |
| POST `/cache/prepare`, `/cancel`, `/clear` | Select `models` relative paths, `warm_ram`, `ram_gib`. Two SSD readers yield to generation. Page cache warming reserves at least 8 GiB or 25% RAM. Drive originals survive failure. |
| POST `/workflows/check`, `/import` | `{workflow,filename}` or `name`. Check additionally accepts `{relative_path}` from the saved-workflow picker, reads at most 16 MiB from the new Drive root, and returns the exact session identity with the receipt. Checks exact Comfy input choices, marks dynamic/unprovable UI widget mappings unresolved. Import requires a safe `.json` filename and refuses conflicting content. |
| POST `/nodes/install`, `/update`, `/remove` | `{id,version,expected_version}`; stable registry versions only. Updates/removals require expected current version. Manager 4.2.2 `/v2/manager/queue/task`, task history, final installed state and CUDA/dependency checks prove the operation. Restart required. |
| POST `/outputs/prepare`, `/ack`, `/resume` | Admission barrier, immutable SHA manifest, exact verified delivery acknowledgment, explicit resume after failure. |
| POST `/outputs/delivery` | PC-only, idle queue, unpaused batch of at most 100 pending files. Returns `{manifest_id,files,delivery:true,paused:false,output_mode:"pc",pending_outputs}`. Controller copies and verifies the batch, then sends `/outputs/ack` with `delivery:true`. Live acknowledgments merge only matching unchanged files and do not replace the final output manifest or prove teardown safety. |
| POST `/outputs/switch` | Internal restart stage after the ComfyUI port closes. Requires `{previous_output_mode,output_mode}`, paused admission, all old outputs captured/acknowledged, verified runtime and no background operations. Commits persistent/memory config without removing either destination. |
| POST `/runtime/save`, `/stop/prepare`, `/restart/prepare` | Preservation, verified stop report, safe restart barrier. Background work and unknown queues block them. |

Model categories: checkpoints, diffusion_models, text_encoders, clip, clip_vision, loras, vae, controlnet, upscale_models, embeddings, unet, llm_gguf, onnx, audio_encoders, model_patches. SSD and Drive use ComfyUI `--extra-model-paths-config`; no global loader patch is installed. Cache invalidation handles controller-managed replacement and startup reconciliation. External Drive edits can require clearing cache/restarting ComfyUI to refresh its file-list cache.

Registry API contracts were checked against the [official OpenAPI](https://github.com/Comfy-Org/registry-backend/blob/main/openapi.yml), the deployed public `https://api.comfy.org/openapi`, and Manager 4.2.2 `common/cnr_utils.py`. Search uses `/nodes/search?search=...`; `/nodes?search=...` silently ignores the keyword. Catalog reads at most two pages of 100 and validates the returned stride and total. The versions endpoint returns an unpaginated array, so the response is bounded to 2 MiB and 5,000 versions before local pagination. Public requests allow no redirects or auth headers and have a 12-second deadline, with three simultaneous reads at most. Installation rechecks the chosen active stable version immediately before adding a Manager task. Registry dependency metadata is not a substitute for the existing dependency/CUDA postcondition checks.

Remote CPU measurement is a nonblocking `/proc/stat` delta sampled at most every five seconds, with the first/failed measurement reported as null. GPU free/total VRAM comes from actual ComfyUI devices. Download snapshots include aggregate `busy` across every job, including jobs outside the displayed page. The runtime operation status records only stage, state, time, elapsed duration, return code and a fixed cause label in `state/operation-status.json`; arguments and subprocess output never enter diagnostics.

## Preservation and delivery

Our small admission node serializes `/prompt` and Manager `/v2` mutations with a stop barrier. It prevents an already-open ComfyUI page from racing a final output capture or runtime save. The owned companion uses an internal bearer header only for its versioned Manager maintenance operations; that header never bypasses generation admission. Generation and Manager queues are checked again inside the exclusive barrier. Busy/unknown state retains the VM. PC files live under `output-pc/<session_id>/`; Drive files live under the new Drive root's `output/`. Capture flushes, hashes and checks files did not change. Acknowledgment requires every relative filename, size and SHA-256 to match, then rechecks source content. PC mode requires the controller's durable SFTP copy first; Drive mode acknowledges verified mounted-Drive files without copying to the PC. `/outputs/resume` reopens admission when any stop step fails.

Continuous delivery leaves admission open. Each pending file is flushed and hashed with before/after metadata checks, copied and hash-verified at the PC, then rehashed at acknowledgment. A new generation can begin during the transfer; new files remain pending, and any changed captured file refuses acknowledgment. Partial filenames are skipped until the final stop gate, which still refuses them. Unchanged acknowledged files are not rehashed on every poll. Receipts are scoped separately to PC and Drive root paths; switching destinations cannot reinterpret a Drive receipt as PC delivery. Final Drive shutdown additionally hashes any inactive PC destination and refuses to stop if unverified temporary PC files remain. Output enumeration streams sorted directory entries with a 10,000-file cap instead of retaining every recursive path at once.

Artifact content consists of core, core environment, MCP environment and locks. Models, outputs, user data, logs, credentials, caches and inherited Colab packages are excluded. Files are sorted, gzip timestamp is zero, and tar ownership/time/modes are normalized. Change detection uses file content, execute bits and registered node state. SHA verification, safe staged extraction, relevant compatibility, selected pointer and last-good pointer guard publication. A save failure leaves the previous selected artifact intact. Restore tries the selected pointer first, then a separately verified, compatible last-good pointer when the selected JSON/archive/extracted runtime cannot be verified. Each candidate gets a fresh stage. Only successful runtime validation and complete local publication allow last-good promotion to selected; the corrupt archive is preserved. If both candidates fail, no runtime components are published. Disk failures do not trigger a misleading fallback. Bootstrap returns sanitized `recovery` metadata describing the pointer, hash, fallback and prior error. Restore uses the same absolute install path; virtual-environment interpreter links point to the current compatible Colab interpreter. Only product-created historical archive hashes are eligible for retention cleanup.

Data exclusions are scoped to direct `ComfyUI/models,input,output,outputs,user,temp,logs`, and Git hooks/logs to the checkout metadata. Dependency and custom-node code named `models`, `input`, or `user` is preserved. Recipe archive schema 2 rejects the earlier artifact that could omit `transformers/models` source; the old bytes are preserved for inspection rather than silently repaired. Runtime validation now imports `CLIPTokenizer` and `CLIPTextModel` without loading model weights. Files-only extraction reconstructs canonical empty `.git/refs` and `.git/objects` before validating a detached checkout; a real Git regression covers the empty-ref case.

Output enumeration explicitly inspects the root, each directory and each file, and refuses unreadable/missing paths, symlinks, devices and traversal errors. Such failures never produce an empty successful manifest. Continuous pending counts use the same bounded enumerator; unknown filesystem state blocks delivery and stop instead of becoming zero.

## Explicit legacy file import

Only the current mounted account's sibling `ComfyColab/models/<known category>` and `ComfyColab/user/default/workflows` are readable sources. The sole category alias is legacy `LLM` to new `llm_gguf`; its model bytes do not import the excluded Huihui integration. There is no automatic migration, external source root, arbitrary URL, credential import, old runtime image, venv, input or output import. Models accept the library's suffix allowlist; workflows must be nonempty JSON objects up to 16 MiB. Both endpoints are authenticated and session-bound like every companion call.

Listing is deterministic and paged, capped at 10,000 matching files. Copies use a 4 MiB buffer, source metadata/hash stability, flushed temporary files, SHA-256 verification and atomic publication that cannot overwrite another writer. Identical existing content returns `unchanged:true`; different content returns `legacy_conflict`. Source and destination ancestor symlinks/traversal are rejected. New model identities and disposable cache/catalog state are updated only after publication verification. Google Drive no-clobber rename support remains an external acceptance check: Linux uses `renameat2(RENAME_NOREPLACE)` or a same-filesystem hard-link fallback and refuses unsupported storage with `atomic_publication_unavailable`. It never falls back to overwrite-capable `os.replace`. See the [Linux rename contract](https://man7.org/linux/man-pages/man2/rename.2.html) and [Python rename behavior](https://docs.python.org/3/library/os.html#os.rename).

The artifact recipe hashes the pinned installation inputs and installed admission guard. The companion/bootstrap transport sources are uploaded fresh and do not invalidate a multi-gigabyte environment merely because download/reporting behavior changes. When modifying dependency resolution, environment layout or install semantics in `bootstrap.py`, bump `install_revision` in `runtime.json`; guard changes and dependency pins invalidate automatically. Archive format changes must bump its recipe schema. Extracted file content, node state and inherited dependency compatibility still undergo their independent checks.

## Verification and remaining external checks

Run `python -m unittest discover -s remote/tests -v` from the repository root. Tests use temporary files and mocked origins/Manager, and include a real local HTTP companion plus a controller/Drive stop boundary. They never touch Colab or an actual Drive.

The 180-second target remains unproven. Initial cold wheel resolution is setup work; later warm starts must be benchmarked from the user's click through Google allocation/auth, Drive mount, artifact restore, all service probes and MCP server_info. Keep unsuccessful runs in the dataset. Real Linux checks are still required for CUDA, venv interpreter restoration, `flock` admission, filesystem durability, Manager registry operations, authenticated providers, SDK transport and Drive latency/quota. Mounted-Drive flush/hash proves the mount's contract; it does not independently query Google cloud replication. CPU mode needs no runtime artifact but still blocks teardown during downloads. Dynamic workflows require ComfyUI execution validation. Third-party nodes outside the registry need a future explicit reproducible-pack design.

Dependencies remain subject to their own upstream licenses; no third-party source was vendored here.

## First clean GPU proof

Use one explicitly owned T4 allocation, a newly created runtime, the new Drive root and PC output mode. Preserve the exact allocation on any failure and reconnect to it; never remount or allocate a replacement to conceal a failed attempt. Record the base Python/ABI/libc, protected Torch/CUDA versions and module locations, all phase times, whole click-to-ready duration, download duration and generation duration separately. Initial setup is distinct from the later 180-second target; neither this procedure nor the CPU proof demonstrates that target. Google documents a 2–3 minute additional cost for selecting a [past runtime image](https://research.google.com/colaboratory/runtime-version-faq.html), so that is not a startup optimization.

Before generation, the official MCP on the actual owned tunnel must return `server_info`: `server.running:true`, `server.url:http://127.0.0.1:8188`, `config.default_workspace:/content/easy-comfy-colab-2/ComfyUI`, and the expected GPU hardware. Also inspect `/system_stats` and `tools/list`; required tools are `server_info`, `validate_workflow`, `run_workflow`, `job`, `fetch_outputs` and `system_stats`. MCP 0.10.0 has grouped `job(action="wait"|"status"|"error"|"queue")`, not a required standalone `wait_for_job`. Its freshness metadata may mark our fixed SHA outdated; do not update pinned components during the proof. [Pinned MCP source](https://github.com/Comfy-Org/comfy-mcp/blob/v0.10.0/src/comfy_mcp/server.py), [CLI environment shape](https://github.com/Comfy-Org/comfy-cli/blob/v1.22.0/comfy_cli/env_checker.py).

The smallest straightforward checkpoint proof uses the [official Comfy SD 1.5 FP16 archive](https://huggingface.co/Comfy-Org/stable-diffusion-v1-5-archive/blob/96a4eb63b0056942bd4c59222cdd5e6e2c9d0f89/v1-5-pruned-emaonly-fp16.safetensors): one 2.13 GB safetensors file containing the checkpoint's diffusion model, text encoder and VAE. Its [model card](https://huggingface.co/Comfy-Org/stable-diffusion-v1-5-archive/blob/96a4eb63b0056942bd4c59222cdd5e6e2c9d0f89/README.md) declares CreativeML OpenRAIL-M and explains the FP16 conversion.
