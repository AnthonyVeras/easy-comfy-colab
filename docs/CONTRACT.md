# Native controller contract (v1)

Each JSONL request is `{ "id": "unique", "action": "session.start", "params": {} }`. Responses are `{ "id": "unique", "ok": true, "result": {} }` or `{ "id": "unique", "ok": false, "error": { "code": "identifier", "message": "sanitized human text" } }`. Unsolicited updates are `{ "event": "progress|state|auth|download", "data": {} }`. No raw shell command is exposed. Python snake_case fields are preserved across bridges.

The shell launches `controller/main.py` during development and the packaged controller in release. UI uses `window.easyComfy.request(action, params)` and `window.easyComfy.subscribe(listener)` returning an unsubscribe function. Browser-only preview must identify itself as offline and never fabricate connected account/session metrics.

`app.snapshot` returns `{accounts, selected_account_id, session, downloads, models, packages, history, preferences, metrics, capabilities, output_delivery}`. Account public shape: `{id,label,email,connected,gpu,output_mode}`. Session shape: `{state,account_id,session_id,phase,started_at,comfy_url,mcp_url,hardware,output_mode,pending_outputs,error}`. State values: `idle,authorizing,allocating,preparing,starting,ready,reconnecting,stopping,error`. Absent measurements are null. Preferences include `language` (`pt-BR|en`), `idle_minutes` (default 0), `balance_alert`, `auto_open`. Local CPU/RAM and remote usage/cache are separately identified; late polling replies must recheck account/session/transport before publication.

Actions: `app.snapshot`, `app.preferences`, `app.diagnostics`, `account.importLegacy`, `account.connect`, `account.submitCode`, `account.select`, `account.remove`, `account.update`, `account.credentials`, `session.start`, `session.cancel`, `session.reconnect`, `session.restart`, `session.stop`, `session.freeMemory`, `session.runtimeSave`, `session.open`, `model.list`, `download.add`, `download.cancel`, `download.resume`, `cache.prepare`, `cache.cancel`, `cache.clear`, `workflow.check`, `workflow.import`, `node.list`, `node.install`, `node.update`, `node.remove`, `drive.copy`, `drive.share`, `history.list`. All account mutations use `account_id`; remote operations bind the owned session. Actions requiring unavailable setup return actionable errors, never fake success.

Remote CLI: `python remote/bootstrap.py --request JSON` produces one JSON result. Bootstrap is uploaded into `/content/easy-comfy-colab-2/remote`; install root `/content/easy-comfy-colab-2/ComfyUI`; Drive root `/content/drive/MyDrive/EasyComfyColab2`. ComfyUI/companion/MCP listen only on remote loopback. Local preferred ports 28188 (ComfyUI), 28190 (companion), 28189 (official MCP). Preflight port ownership before allocation; return actual tunnel URLs. Never touch legacy 18188/18189.

Companion HTTP API on remote 8190: `GET /health` returns account_id/session_id/nonce; `GET /snapshot`, `GET /models`, `GET /downloads`, `POST /downloads` with `{urls,category,parallel,tokens}` (tokens only in memory), `POST /downloads/{id}/cancel|resume`, `POST /cache/prepare|cancel|clear`, `POST /outputs/prepare|ack`, `POST /runtime/save`, `POST /nodes/install|update|remove`. Mutations require a per-session bearer token; every call checks expected session identity. Output prepare returns files with relative path,size,sha256; ack only after durable local copy verified. Runtime save result `{verified,changed,manifest}`. Health does not expose bearer token.

Safety: no arbitrary endpoint stop; no overwrite of conflicting model identity; no direct teardown after server readiness without output/runtime gates; never read old runtime image. Persist node/version manifest and verified last-good runtime artifact. Use ComfyUI standard path configuration for model cache rather than replacing global loader functions.

## ComfyUI browser bridge / Easy Install base (0.1.1)

The pinned frontend's `window.__comfyDesktop2.downloadModel(url,name,directory)` hook serves individual and bulk missing-model downloads. The owned `easy_model_download` custom node proxies JSON from same-origin loopback `/easy-comfy/model-download` and its bounded job-status route to VM companion port 8190. The browser receives job IDs/progress only; the node supplies per-session identity/authentication server-side. Redirects and environment proxies are disabled for this relay. Bulk admission is serial; byte transfers remain parallel in the existing remote queue. Errors never trigger a browser file download.

`POST /credentials/models` replaces only the companion's in-memory provider map. The controller calls it after owned identity verification and after a credential change for the active account. `/comfy/downloads` validates URL, filename, category and optional checksum; status excludes URLs and auth. Runtime preservation verifies the installed bridge bytes.

Easy Install is assembled from a pinned MAC-Linux source catalog, verified Registry artifacts or exact Git fallback pins, safe workflow JSON examples and a protected wheel dependency closure. No upstream Bash installer, desktop helper, arbitrary install.py or replacement Torch/CUDA environment is executed. Base source receipts, tracking and license/provenance are artifact components. Recipe revision 3 includes the base manifest and bridge hashes; previous artifacts remain intact but cannot satisfy the new recipe. Base packages cannot be independently changed through the app; optional stable Registry nodes retain the existing management flow.

## Parity additions

- `account.usage`: reads the selected/explicit account's Colab consumption API without allocating, recovering or mounting a VM. `{account_id,force?}` returns `{account_id,balance,rate,status,checked_at,error_code}`. A per-account, subject-bound memory cache lasts 60 seconds; force bypasses it. Errors clear the previous reading, expose a classified code and never become zero. Snapshots include `account_usage` and merge only the selected account's balance/rate into metrics. The renderer queries after the first local snapshot, on account changes and regular refresh; manual Refresh forces a query. Late replies cannot update another account's display. Benchmark mode blocks cloud usage reads.

- `download.list`, `workflow.list`, `node.catalog`, `node.versions`: bounded pages with offset/limit/total; catalog query and registered node/version identifiers validated. Saved workflow checks accept only relative JSON paths within the new Drive workflow directory. Validation evidence belongs to the selected account, session and file.
- `history.export`: all retained receipts up to 2,000, using the same filters as `history.list`. Native wrappers show a JSON save dialog; cancellation is reported without a successful save. Credentials and raw operation parameters are excluded.
- `legacy.list`, `legacy.import`: explicitly selected model/category or JSON workflow from fixed legacy Drive library roots of the active account. One file is copied into the new library after integrity checks; originals and the old image are untouched. Conflicting destinations require another name. Imports require the owned account's Drive-mounted CPU/GPU session.
- `session.restart` accepts `output_mode: pc|drive`. Before changing mode in the same VM, pause admission, verify old output delivery and preserve the runtime. Commit account preference only after the actual new mode is confirmed; failures reconcile the owned runtime for recovery.
- `output_delivery` reports verified continuous PC delivery or its error. `POST /outputs/delivery` selects at most 100 stable pending files without pausing inference; `POST /outputs/ack` with `delivery:true` acknowledges only durable checksum-verified copies. Final shutdown retains its separate admission barrier, complete output inventory and runtime preservation gates, including previous PC destinations.
- `ECC_BENCHMARK=1` uses empty isolated local data and blocks all cloud/credential-import mutations and remote polling. Benchmark cleanup never owns a VM.

## Native MOSS LoRA training

`training.status` reads the owned companion; `training.import` uploads a bounded ZIP by SFTP and verifies its SHA-256. `training.prepare` creates/reuses a content-addressed Drive project and prepares the separate Linux environment/caches. `training.start` and `training.resume` are explicit separate user actions. `training.cancel` signals only the verified worker process group. `training.preserve` verifies stable Drive files before clearing admission; `training.export` copies a real ComfyUI adapter to the new model library. Every action requires the active `account_id` and `session_id`. No user Python/configuration source, arbitrary command, URL or checkpoint path is accepted.

Companion snapshots include `training.busy` and `training.preserved`. Missing/unknown training state prevents idle shutdown and continuous PC output capture. The durable `training-active` marker blocks ComfyUI prompt admission while the trainer runs. All preservation/restart/stop gates and free-memory operations consult the same training safety state. Training outputs always use the Drive tree, independent of PC image delivery. See MOSS_TRAINING.md for limits, pins and recovery.
